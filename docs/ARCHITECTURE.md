# Архитектура проекта

Веб-клиент — SPA на Vanilla JS/Vite: браузер открывает маршруты `/posts/:id`, `/users/:name` и через `/api/v1/` получает JSON. Vite во время разработки проксирует `/api` на `127.0.0.1:8000`; в контейнерах этим занимается Nginx. Локальные черновики и офлайн-подборки сохраняются в браузере.

FastAPI принимает/валидирует запросы Pydantic-моделями, а SQLAlchemy ORM использует сессии для запросов к PostgreSQL. Авторизация: Argon2id для паролей, JWT с подписью HS256 в HttpOnly-cookie; CSRF cookie + заголовок и проверка Origin для записывающих запросов; `auth_sessions` используется для отзыва токена при выходе.

## Эволюция схемы

- `0001_initial`: таблицы `users`, `posts`, `topics`, `tags`, `post_topics`, `post_tags` и ограничения.
- `0002_auth_sessions`: таблица сессий для отзыва JWT при logout.
- `0003_views_and_usernames`: счётчик просмотров и единый нижний регистр `username`.

`create_all()` не заменяет миграции: оно не обновляет уже существующие таблицы. Скрипты миграций проверяются на чистой и заполненной PostgreSQL. Для быстрых unit/HTTP-тестов используется SQLite, PostgreSQL-специфичные требования проверяются отдельным контейнерным сценарием.

## Контейнерный стек

```text
Браузер → 127.0.0.1:8088 → web:Nginx:8080 → api:FastAPI:8000 → db:PostgreSQL:5432
                                      ↘ контейнер migrate → Alembic upgrade head ↗
```

Nginx доступен с хоста только по loopback; FastAPI доступен через `frontend_net`, PostgreSQL — только через `data_net` с `internal: true`. Время жизни контейнера отдельно от времени жизни volume с данными. `read_only`, `tmpfs`, `cap_drop`, `no-new-privileges` и непривилегированные UID уменьшают потенциальный ущерб при компрометации.

Скрипты в `scripts/` проверяют именно эту конфигурацию, не создавая вторую копию приложения.
